## 实现说明

### 运行方法
```ts
import { createBm25TextPipeline } from './src/main/retrieval/index.js';

const pipeline = createBm25TextPipeline();
const analyzed = pipeline.analyze('今天状态真好');   // { tokens, tf, docLen } 写入侧
const query = pipeline.queryTokens('今天状态真好');   // 去重 token 数组 查询侧
```

写入与查询共用同一 `normalize` → `tokenize` 路径（`tokenize` = `jieba-wasm.cut_for_search` + 过滤空 token/纯标点，保留 CJK/ASCII/emoji）。分词器随模块 import 同步初始化一次，实时路径不复用初始化。

### 测试命令
```bash
npm run typecheck && npm run test:contracts && npm run test
# 专项：npx vitest run tests/unit/retrieval/bm25-pipeline.test.ts
```

### 已知限制
- `BM25_NORMALIZATION_VERSION_V1` 合并规范化与热词词表版本；CONTRACT §4 要求"同义词词表版本"单独写入 collection metadata，MVP 以单一版本号表示，POC 校准改热词表时需同步 bump。
- 热词表默认空，机制版本化可注入；实际词条待 POC 以甲方样本校准。

## 实现说明

### 运行方法
```ts
import { evaluateRetrieval, evaluateDirectPush, buildRetrievalResult } from './src/main/retrieval/index.js';

const evaluated = evaluateRetrieval(raw, { topK: 10 });
const decision = evaluateDirectPush(evaluated.mergedTopK, {
  personaId, personaVersion, directPushThreshold: 0.85, // 后者来自 settings.internalRetrieval
});
const result = buildRetrievalResult({
  traceId, calibrationVersion: evaluated.calibrationVersion,
  goldenHits: evaluated.goldenHits, preHits: evaluated.preHits,
  mergedTopK: evaluated.mergedTopK, directPush: decision,
});
// decision.eligible=true → 直出 decision.pointId 对应 golden reply/cues，不调用 LLM
```

### 设计要点
- **直出条件**（CONTRACT §4.2 / ARCH §4.3）：需全部满足——Top-1 存在、`collection='golden_set'`、`retrievalConfidence >= threshold`（相等可直出）、`enabled=true`、`is_bad_case=false`、`persona_id`/`persona_version` 与当前一致。任一不满足（含 Top-1 来自 pre_set、空输入）→ `eligible=false, reason='LLM_REQUIRED'`。
- **fail-closed**：`directPushThreshold` 非有限数或越界 `[0,1]` 抛错；`buildRetrievalResult` 拒绝"非 eligible 却带 pointId"的不一致输入；结果经 `RetrievalResultV1Schema.parse` 运行时校验。
- **契约衔接**：`RetrievalResultV1`（M3-07 加入）在此填充 `directPushEligible`/`directPointId`；非 eligible 时省略 `directPointId`。
- 直出 payload 的输出校验（长度/安全/人设复验）属 **M5-06** 共用输出校验器；trace 状态机落地属 **M5-07** 编排。M3-08 只产出决策。

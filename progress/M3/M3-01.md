## 实现说明

### 运行方法
```ts
import { QdrantSidecarManager } from './src/main/qdrant/index.js';

const manager = new QdrantSidecarManager({
  binaryPath: 'assets/qdrant_linux',      // Windows 用 assets/qdrant_windows.exe
  dataDir: '<应用数据目录>/qdrant',         // host/port/存储由管理器物化
  configTemplatePath: 'resources/qdrant-config.yaml',
  httpPort: 6333, grpcPort: 6334,
  expectedVersion: '1.19.0',
});
const handle = await manager.start();      // { pid, httpPort }
await manager.isHealthy();
await manager.stop();
```

### 设计要点
- **打包内置配置文件**（用户决策）：模板 host 固定 127.0.0.1，每次启动物化 `<dataDir>/qdrant-config.yaml`（绝对存储路径 + 端口）并以 `--config-path` 启动；用户对 host/port/存储的手动改动在下次启动被还原。
- **进程清理**（文档化偏差）：纯 Node 无法创建 Windows Job Object，用 POSIX `kill(-pid,SIGKILL)`（detached 进程组）+ Windows `taskkill /PID /T /F` 满足"无孤儿"不变量；M3-09 POC 在真实 Windows 验收。
- **错误映射**：二进制缺失/sha256 不匹配/端口占用/启动退出 → `SidecarStartFailedError`(E_SIDECAR_START_FAILED)；存活但健康超时 → `QdrantUnavailableError`(E_QDRANT_UNAVAILABLE)，code 引用 contracts `DomainErrorV1Schema`。

# M6-10 打标与修订入口

## 状态
已完成（2026-08-23）

## 实现说明

### 包含范围
- 契约（沿用 M6-07 预置 + 补充）：`AuditSubmitLabelRequestV1`（traceId UUID v7 / `expectedRevisionNo` 乐观锁 / `score` 0–100 / 可选 `correctedQuickReply`+`correctedCues`，superRefine 强制同现）、`AuditSubmitLabelResponseV1`（仅用户可见 `labelStatus`，CONTRACT §7）；`src/contracts/test` 已有 5 例
- `AuditStoreWorker.submitLabel(input)`：单事务写 `suggestion_feedback` revision（`revision_no = MAX+1`，`UNIQUE(trace_id, revision_no)` 修订而非覆盖）→ 更新 `audit_trace.label_status/current_feedback_id` → 返回 labelStatus；**不写 `qdrant_sync_job`（回流/outbox 属 M7-01）**，`sync_status` 保持默认 `NOT_REQUIRED`
  - 状态派生（UI §8.2）：有修正 → CORRECTED；score=0 → REJECTED；否则 ACCEPTED
  - 乐观锁：`COUNT(*) FROM suggestion_feedback` 与 `expectedRevisionNo` 不一致 → `AuditStateInvalidError`（并发编辑被拒）
  - `persona_id/persona_version` 取自 trace workflow 的 `PERSONA_VERSION_SNAPSHOT`（不可变 PersonaSnapshot）
  - `source_collection/source_point_id` 取 `DIRECT_DECISION`（golden 直出）；`is_bad_case` = REJECTED 且无修正 且 golden 直出（M7-03 规则前置，outbox 仍归 M7）
  - `correction_envelope` 用 FieldEncryptor AES-GCM 加密（AAD: suggestion_feedback + snapshotId + CORRECTION_JSON）
  - 无最终建议的 trace → `AuditStateInvalidError('trace has no final suggestion; no label required')`
- `audit-control-handlers`：submitLabel 校验 + 修正答案分 >0 约束；`audit-control-ipc` 注册 `audit.submitLabel`（guarded handler 仅主窗口）
- preload `audit.submitLabel`
- `AuditPage.tsx` LabelForm：认可/不认可 radio、0–100 分、不认可+修正 → 短回复+2–3 提词、默认 85、编辑本次打标产生新修订、保存失败保留输入 + 显示错误、成功后刷新列表；绝不展示 golden/sync/threshold/bad-case
- 测试：`tests/unit/audit/audit-submit-label-handlers`（6 例：accept/reject/corrected/修正0分拒/unknown 字段拒/非 v7 拒）、T-AUD-001 集成 +3（写 revision 更新 trace 且无 outbox、revision 递增 + 乐观锁拒、无建议 trace 拒）

### 产品取舍（已确认）
- M6-10 只做「打标与修订入口」：反馈修订 + trace 用户可见状态持久化；`qdrant_sync_job` 事务/outbox/golden 回流是 **M7-01**「实现 feedback 修订事务和 outbox」，本批不创建 job（集成测试显式断言 job 数为 0）
- 乐观锁用 `expectedRevisionNo`（既有 schema）：渲染端 UNLABELED 传 0、已打标传 1；并发编辑返回「打标参数不合法」由 UI 保留输入

### 不包含范围
- IPC 全量越权矩阵（M6-11）
- outbox/golden 回流（M7-01/02/03）

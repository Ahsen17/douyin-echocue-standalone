# M6-03 直播间与 AI 配置页

## 状态
已完成（2026-08-22）

## 实现说明

### 包含范围
- `src/main/config/config-control-handlers.ts`：`update()` 扩展 provider 写通道——`providerId=slugify(displayName)`（`^[a-z0-9_-]{1,64}$` 匹配，非 ASCII 全空回落 'default'）；providerId 与旧配置一致则保留原 credentialRef，否则 `CredentialStore.buildCredentialRef(providerId)`；host/adapter 变更由 `ProviderConfigService.updateProviderConfig` → `invalidateIfProviderChanged` 自动失效旧 key；损坏 settings 统一抛「配置读取失败…」（与 get() 一致）；`ConfigUpdateRequestV1Schema` 的 adapter 枚举仅 DEEPSEEK/OPENAI_COMPATIBLE（ANTHROPIC 边界即拒）
- `src/renderer/main/provider/provider-form.ts`（纯函数）：`initialForm`（apiKey 恒空，ANTHROPIC 回落 OPENAI_COMPATIBLE）、`buildConfigUpdate`（trim + 空 room 省略）、`validateProviderForm`（HTTPS 无 userinfo/query/hash、必填字段）
- `src/renderer/main/provider/provider-save.ts`：`saveProviderConfig` 两段式保存（config.update 先 → key 非空则 setApiKey 后，返回视图合并 `apiKeyConfigured`，避免首存后状态陈旧）
- `src/renderer/main/pages/RoomAiPage.tsx`：直播间标识 + AI 服务表单（服务商/适配器/Base URL/Model ID/API Key password + placeholder 已配置/未配置）+ 测试连接三态（配置有效/认证失败/服务暂不可用）+ 清除 Key 本地确认 + 保存失败保留输入 + 运行中提示「已保存；将在下次启动服务时生效」
- 测试：provider-form（initialForm 不回显 / HTTPS 校验各失败）、provider-save（首存合并 apiKeyConfigured / 空 key 不 set / trim）、config handler provider 写通道（providerId 派生 / credentialRef 稳定 / host 变更失效 / ANTHROPIC 拒绝 / 隐私断言）

### SubAgent 自检修复项
- P1：首存 API Key 后页面 `apiKeyConfigured` 陈旧（setConfig 用了 setApiKey 前的视图）→ 提取 `saveProviderConfig` 合并 setApiKey 结果
- P2-1：apiKey 未 trim（空白也存储）→ saveProviderConfig 内 `trim()` 后判断
- P2-2：serviceState 为 null 时漏「下次启动生效」提示 → 保守处理（非已知 STOPPED 即提示）
- P2-4：update provider 分支损坏 settings 抛原始 ConfigCorruptError → try/catch 统一友好错误
- P2-5：补 provider-save 单测覆盖两段式保存/首存状态

### 不包含范围
- persona 写通道与团队/人设页（M6-04）
- safety.* IPC 与安全页（M6-05）
- 浮窗偏好页与 overlay（M6-06/07）、诊断页完整 UI（M6-08）、审计（M6-09/10）

## 实现说明

### 包含范围
- 通道：`src/shared/ipc-channels.ts` 新增 `OverlayPreferenceUpdate: 'overlay.preference.update'`（CONTRACT §7 主窗口白名单通道）
- `src/main/config/config-control-handlers.ts`：`ConfigControlHandlers.updateOverlay(raw)`——复用 `OverlayPreferenceV1Schema`（strict，7 字段）校验，失败「浮窗偏好不合法」→ `settings.update({ overlay })` → 返回更新后偏好；deps 可选 `overlayWindow.applyPreferences`（M6-07 才传入，live-apply 接线预留）
- `config-control-ipc.ts`：经 `createGuardedHandler(isTrustedSender)` 注册 `OverlayPreferenceUpdate`，`overlayWindow` 透传
- preload：`overlay.updatePreferences(prefs) → OverlayPreferenceV1`
- `src/renderer/main/overlay/overlay-prefs.ts`（纯函数）：`DEFAULT_OVERLAY_PREFS`（镜像 SettingsStore defaults）、`prefToForm`/`formToPref`（秒↔ms、%↔小数）、`validateDurationSec`（1–60 整数秒）
- `src/renderer/main/pages/PreferencesPage.tsx`（替换占位）：`config.get()` → 表单（展示时长/宽度/高度/透明度 %range/字号 %range/主题/点击穿透）+ `OverlayPreview` 实时预览 + 保存/恢复默认 + 点击穿透提示「将无法直接拖动，请在偏好页关闭后调整」+ 失败保留输入 + 空/错误/重试态
- `displayDurationMs` 接线：`SuggestionOrchestratorDeps.getDisplayDurationMs?` → `SuggestionAttemptOrchestrator.display()` 按次读取 `(await getter?.()) ?? displayDurationMs ?? 10000`（UI §7「应用于下一次展示」）；`create-controller.ts` 传 `async () => (await settings.get())?.overlay?.durationMs ?? 10000`；保留 `displayDurationMs` 作 M5-08 测试兜底
- 测试：config-handlers +5（持久化/越界拒/部分拒/strict 额外字段拒/边界 opacity 0.19 与 60000 过/live-apply 调用）、overlay-prefs 9、orchestrator +2（getter 优先于固定值、getter 短时长触发 HIDDEN）

### 产品取舍（已确认）
- 偏好更新走独立 `overlay.preference.update` 通道（CONTRACT §7 白名单），不并入 `config.update`；读路径沿用 `config.get`（ConfigViewV1 已含 overlay）
- 展示时长按次读取 settings，偏好变更对下一次展示生效，无需重启服务
- 「恢复默认」= 写回 DEFAULT_OVERLAY_PREFS（与 SettingsStore defaults 同值）

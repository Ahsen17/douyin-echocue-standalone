# M6-05 安全与禁忌页

## 状态
已完成（2026-08-22）

## 实现说明

### 包含范围
- 契约（`src/contracts/src/schemas.ts` + docs 同步逐字节）：`CompileErrorV1`（clauseIndex≥-1）/`SafetyPolicyVersionMetaV1`（status 四态）/`SafetyPolicyCurrentV1`（policyText≤50000、keywords≤50×≤64、validationErrors）/`SafetyPolicyViewV1`（activeVersion?/current?/versions）/`SafetySaveDraftRequestV1`/`SafetyPublishRequestV1`/`SafetySaveDraftResultV1`；上限与 persona 对齐；`strictObject` 拒 compiledRules 等多余字段
- `src/main/safety/safety-control-handlers.ts`：`get`（active=`getActivePublishedVersion()` 的 meta；current=最新 DRAFT **或 INVALID** 否则 active 否则 null；`readPolicy` 丢弃 compiledRules）、`saveDraft`（createDraft→readPolicy→`{meta, valid, errors 中文化}`）、`publish`（publishDraft + activatePublishedVersion→meta）；`translateSafetyError` 六类领域错误中文映射；`localizeCompileError` 覆盖 5 种编译器英文消息
- `safety-control-ipc.ts` 经 `createGuardedHandler` 注册 `safety.get/saveDraft/publish`；barrel 导出；`main/index.ts` 注册 wire
- preload：`safety.{get,saveDraft,publish}` 契约类型
- `src/renderer/main/safety/safety-logic.ts`：`splitClauses`（与编译器正则逐字一致，clauseIndex 只计非空子句）/`localizeErrors`（子句定位）/`validateKeyword`（空/重复/超 64）/`formatSafetyVersion`
- `src/renderer/main/pages/SafetyPage.tsx`：单工作区（风险说明 + 边界 textarea + 关键词 tag 增删 + 字段级校验 + 校验并发布 + 徽标「已发布/需修改/草稿待校验」+ INVALID 就地列错误禁止发布 + 运行中提示下次启动生效 + 失败保留输入 + 空/错误/重试态）
- 测试：契约 24 例（含 compiledRules 拒收）、handler 15 例（真实 Store + SettingsStore，含 INVALID 草稿保持为 current / settings 指针更新 / SUPERSEDED / 隐私断言）、safety-logic 18 例

### SubAgent 自检修复项（两轮）
- P1-1（中）：`get()` 的 current 选择排除 INVALID 草稿 → 刷新后「需修改」内容与编译错误不可见、renderer 错误分支成死代码 → current 取 `DRAFT || INVALID`，补「INVALID 草稿保持为 current 且 validationErrors 非空」用例
- P1-2（低）：`toCurrentContent` 的 validationErrors 为编译器原文（英文）→ 一并 `map(localizeCompileError)`（get 路径也中文化，避免双重翻译）
- P1-3（低）：隐私断言 `JSON.stringify(Error)` 为 `{}` 空跑 → 错误路径改 `String(err)`
- P1-4（低）：compiledRules 结构断言在空库上 `view.current` 空跑 → 先 saveDraft 再 get()

### 产品取舍（已确认）
- 空策略（空 textarea + 空关键词）可编译通过并发布：内置 detector 恒运行、非 fail-open；UI 字段级校验仍拦截空白/重复/超长关键词。与契约「accepts empty policy」用例一致。

## 实现说明

### 运行方法
```ts
import { SafetyPolicyStore, SafetyEngine, normalizeComment, evaluateInputSafety } from './src/main/safety/index.js';

const normalizedText = normalizeComment(rawText);      // regex→NFKC→小写→空白折叠

// 纯函数输入检查（已发布策略编译产物）
const decision = evaluateInputSafety({ normalizedText, compiledRules }); // { allow, reason, matchedRule }

// 绑定快照的引擎（settings.activeSafetyPolicyVersion → readPolicy）
const engine = new SafetyEngine(policyStore);
const d = await engine.checkInput(normalizedText);     // 无激活版本/指针失效/解密失败 → SAFETY_ENGINE_ERROR
```

## 完成标准验收

- [x] 规范化：regex 去 URL → Unicode NFKC（全/半角统一）→ ASCII 大小写折叠 → 空白折叠+trim；幂等；不改变审计原文
- [x] 过滤顺序（ARCH §4.4）：内置 8 类基础风险/PII detector → 编译 KEYWORD → 编译 REGEX → 编译 TOPIC_PHRASE；`RULE_TYPE_PRIORITY` 重排编译器数组序，保证固定评估顺序
- [x] 任一命中 → `{ allow:false, reason: SafetyReasonCodeV1, matchedRule }`；safe → `{ allow:true }`
- [x] fail closed：无激活版本 / compiledRules=null / 未知 ruleType / 非法正则 / 检测异常 → `SAFETY_ENGINE_ERROR`，绝不静默放行
- [x] SafetyEngine：仅执行已发布版本的确定性编译结果；指针失效（SUPERSEDED）/ 解密失败 → SAFETY_ENGINE_ERROR
- [x] 契约：T-SAFE-001 fixture 运行时 INPUT 用例全覆盖（PII / ABUSE / allow / engine-failure / TEAM_FORBIDDEN 编译规则）
- [x] 内置词表保持中性：移除高误杀词 `攻击`、`隔壁`，POC（M2-06）校准后再固化
- [x] 隐私：新增代码无日志输出；测试仅用合成占位文本；`matchedRule.text` 为策略规则文本非弹幕原文

## 关键不变量

- 规范化确定性：`toLowerCase()` 与宿主 locale 无关，同原文必然同 normalizedText
- 评估顺序固定：内置优先于编译，KEYWORD → REGEX → TOPIC_PHRASE（与编译器产出顺序无关）
- fail closed：策略缺失/损坏/引擎异常一律 SAFETY_ENGINE_ERROR，绝不无规则放行
- 输入过滤与后续输出复验（M5-06）必须引用同一个已发布 safety_policy_version
- 原文用于审计，normalizeComment 只产出新字符串

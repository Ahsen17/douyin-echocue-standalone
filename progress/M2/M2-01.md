## 实现说明

### 运行方法
```ts
import { PersonaStore } from './src/main/persona/index.js';
const store = new PersonaStore({ dbPath, migrations, keyManager, keyVersion });
store.createPersona({ personaId, displayName, isPrincipal, aliases });
store.updatePersona(personaId, { displayName, isPrincipal });
store.deletePersona(personaId);
store.getPersona(personaId);
store.listPersonas();
store.listAliases(personaId);
store.addAlias(personaId, { aliasText, aliasKind, enabled });
store.updateAlias(aliasId, { aliasText, aliasKind, enabled });
store.deleteAlias(aliasId);
store.close();
```

## 完成标准验收

- [x] persona/persona_alias 增删改查（同步短事务，构造与 AuditStoreWorker 同构，经 MigrationRunner 自开 WAL 连接）
- [x] 别名唯一：`UNIQUE(persona_id, alias_text)`，重复抛 `AliasDuplicateError`（E_PERSONA_ALIAS_DUPLICATE）；跨 persona 同文本允许（DDL 仅按 persona 唯一）
- [x] 主要出镜唯一：第二个 principal 被拒（E_PERSONA_PRINCIPAL_CONFLICT），DB 部分唯一索引 `ux_persona_one_principal` 兜底（集成测试直接 SQL 验证）
- [x] 删除主要出镜前拒绝：`deletePersona` 对 `is_principal=1` 抛 `PersonaPrincipalDeletionError`（E_PERSONA_PRINCIPAL_DELETE_REJECTED）
- [x] principal 迁移原子性：升级本行的同时降级旧 principal，同一事务，索引不观察到两个 principal
- [x] 删除级联：单事务按 FK 顺序删 persona_version → persona_alias → persona；被 suggestion_feedback 引用时 FK 违例映射为 `PersonaReferencedError`（E_PERSONA_REFERENCED，携带 personaId）
- [x] 元数据只读：`listPersonas`/`getPersona`/`listAliases` 仅返回 id/显示名/is_principal/active_version/时间戳/计数，不触碰任何 content/envelope 列
- [x] 参数校验：personaId/displayName/aliasText trim + 非空；alias kind 白名单 NAME/NICKNAME/ALIAS/TYPO_VARIANT
- [x] DB 打开失败 → `PersonaStoreUnavailableError`（E_PERSONA_STORE_UNAVAILABLE）；写失败 ROLLBACK 后同码

## 关键不变量

- 所有写操作为单个 SQLite 事务，失败即 ROLLBACK；类型化错误不被包装，调用方可区分用户输入错误与存储故障
- 不持有人设正文：本模块不解密、不读取 `persona_version.content_envelope`（M2-02 扩展时仅限 main 进程路径）
- 别名 ID 为 `randomUUID()`（v4），非契约字段
- 隐私断言采用可识别标记字节植入 `content_envelope` 后校验输出，非列名形式化检查

## 实现说明

### 运行方法
```ts
import { DouyinLiveSidecarManager } from './src/main/douyin/index.js';

const manager = new DouyinLiveSidecarManager({
  binaryPath: 'assets/douyinLive_linux',   // Windows 用 assets/douyinLive_windows.exe
  dataDir: '<应用数据目录>/douyin',          // 二进制工作目录
  port: 1088,
  expectedVersion: '2.2.0',
});
const handle = await manager.start();       // { pid, port }
await manager.isHealthy();
await manager.stop();
```

### 设计要点
- **启动方式实测**：`douyinLive --port <port>` 直接监听；`--version` 输出 `tag=v2.2.0 ...`。启动日志输出到 **STDOUT**（含 `addr=ws://127.0.0.1:<port>`），因此管理器双接管 stdout+stderr（偏离计划的 `['ignore','ignore','pipe']`，为必要修正）。
- **端口所有权校验**（实测发现）：二进制在端口被占时**不失败**，自动改绑 `port+1` 并打印真实 addr。管理器从启动日志解析实际绑定端口（`parseBoundPort`），仅当与请求端口一致才判 ready；不一致 → `E_SIDECAR_START_FAILED`，满足"端口占用不得连接外部进程"。健康探测用 TCP 端口连通（douyinLive 是 WS 服务，无 HTTP /readyz）。
- **进程清理**（文档化偏差，沿用 M3-01）：纯 Node 无法创建 Windows Job Object，用 POSIX `kill(-pid,SIGKILL)`（detached 进程组）+ Windows `taskkill /PID /T /F`；M4-05 真实 Windows POC 验收。
- **错误映射**：二进制缺失/sha256 不匹配/版本过低/端口占用/启动退出 → `SidecarStartFailedError`(E_SIDECAR_START_FAILED)；存活但启动超时 → `SourceUnavailableError`(E_SOURCE_UNAVAILABLE)，code 引用 contracts `DomainErrorV1Schema`。
- **生命周期边界**：本任务仅实现进程管理，不接 WS/状态机/门禁；`roomReference` 选项（计划规格）延至 M4-02 ws-adapter 使用，故本任务 types 未含该字段。

### 已知限制
- Job Object 未实现（纯 Node 限制），用 taskkill/进程组清理替代，见上。
- 二进制入库后本地（Linux）与 Windows CI 均真实运行集成测试；`describe.skipIf` 仅作二进制缺失防御。
- 依赖真实开播房间的 douyinLive 连通性验证归 M4-05 POC。
- 端口占用拒绝用例仅在 Unix 有效：Windows SO_REUSEADDR 允许 Go 二进制与现有监听共享端口，绑定冲突不触发；真实 Windows 行为在 M4-05 POC 验证（测试 `it.skipIf(win32)`）。

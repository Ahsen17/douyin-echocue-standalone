# M5-03 DeepSeek 首个 adapter

## 状态
已完成（2026-08-22，SubAgent 自检通过）

## 实现说明

### 包含范围
- `openai-compat.ts`：共享 `OpenAiChatCompletionsProvider` 基类（M5-04 复用）——构造 `POST {baseUrl}/chat/completions`（无 tools、非流式、json_object），`buildChatCompletionsRequest` 纯函数，transport 错误映射（NETWORK→NETWORK、TIMEOUT→TIMEOUT、ABORTED→ABORTED、REDIRECT/VALIDATION→PROTOCOL），`getAuditRecord()` + `buildAuditRecord()`（rawRequest 白名单字段，Key 深度剥离）
- `deepseek.ts`：`DeepSeekProvider extends OpenAiChatCompletionsProvider`，adapterType='DEEPSEEK'
- `parse.ts`：`parseProviderResponse` 纯函数（无 I/O，可被 fixture 直接驱动）——200+JSON→ok；tool_calls/content null/非字符串→PROTOCOL；JSON 解析/schema 失败→OUTPUT_INVALID；非 200→HTTP 状态映射；错误分支也提取 providerRequestId
- 契约：权威 `contracts-v1.ts` 新增 `ProviderFixtureCaseV1Schema`（含收紧的 `ProviderFixtureResponseV1Schema`/`ProviderFixtureExpectedV1Schema`，非 unknown），同步 contract package + schemas.test.ts
- 填充 `tests/contract/T-PROV-001` 全部 5 用例：fixture 逐条经 schema 校验 + 驱动 parseProviderResponse + timeout 用例接 provider 真实驱动

### 不包含范围
- OpenAI-compatible 独立 adapter 类（M5-04，复用本任务基类）
- Prompt 渲染（M5-05）、输出校验器（M5-06）、编排（M5-07）

### 关键决策
- DeepSeek 与 OpenAI-compatible 共享同一 OpenAI-compatible 请求/解析/错误契约，故实现共享基类 `OpenAiChatCompletionsProvider`，DeepSeek 只设 adapterType——证明业务层无供应商硬绑定
- `parseProviderResponse` 为纯函数，T-PROV-001 直接以 fixture 驱动，契约测试真实验证解析逻辑而非空壳
- `buildAuditRecord` 的 rawRequest 用 `buildChatCompletionsRequest` 的白名单字段（model/stream/response_format/messages），且对 rawRequest/rawResponse 做 apiKey 深度剥离（`[REDACTED]`）；transport 错误路径也产生审计记录（rawRequest + normalizedError）
- providerRequestId 取自响应 body `id`，成功与错误分支均提取
- SubAgent 自检修正：审计记录补全（normalizedError/providerRequestId/错误路径）、`getAuditRecord()` 并入 TextGenerationProvider 接口、基类改名避免与 M5-04 撞名、adapterType 收敛为 `DEEPSEEK|OPENAI_COMPATIBLE`、fixture 经 schema 校验闭环、timeout 用例接 provider

### 遗留（M5-07 处理）
- `lastAuditRecord` 可变实例态依赖"单显示窗口串行生成"约束；多直播间场景需将审计记录随结果返回而非 getter 侧信道（记录于 M5-07 编排设计）

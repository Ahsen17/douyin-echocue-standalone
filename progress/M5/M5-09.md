# M5-09 实现生成路径全量审计快照

## 状态
已完成（2026-08-22）

## 实现说明

### 包含范围
- `src/main/suggestion/SuggestionAttemptOrchestrator.ts`：LLM 路径补四角色快照（LLM §7）——
  - `RENDERED_PROMPT`（PROMPT_TEXT）：随 `PROMPT_RENDERED` transition 写入，含 templateVersion/assemblerVersion/system/user/truncationLog/persona_id/version/content_hmac/safetyVersion/topK(caseId+collection)
  - `LLM_REQUEST_META`（PROVIDER_META_JSON）：随 `LLM_PENDING` transition 写入，含 providerId/adapterType/baseUrlOrigin/modelId/callMode/startedAt/deadline/sessionId/windowVersion
  - `LLM_RAW_RESPONSE`（PROVIDER_RESPONSE_JSON）：随 `GENERATED` transition 写入，含 providerRequestId/httpStatus/rawResponse（provider 已 scrubbed）/completedAt
  - `LLM_PARSED_OUTPUT`（SUGGESTION_JSON）：随 `GENERATED` transition 写入，含 quickReply/cues/parserVersion
  - 结构调整：config/凭证解析提前到进入 `LLM_PENDING` 之前，使请求元数据可随 `LLM_PENDING` 落库；缺配置/密钥仍先进 `LLM_PENDING` 再 `fail()`（保留 LLM_PENDING→FAILED 唯一 FAILED 边）
- `src/main/storage/AuditStoreWorker.ts`：新增 `getTraceWorkflow(traceId)` 读取解密（transitions 按 sequence 排序 + 各 transition 的 snapshots 解密回放，未知 trace 返回 null）
- `src/main/provider/{types,openai-compat}.ts`：`ProviderAuditRecord` 增加 `providerStatus`（LLM_RAW_RESPONSE httpStatus 数据源）
- `docs/06-data-interface/Echocue-数据模型、接口与实时事件协议-v0.1.md`：CONTRACT §6 ProviderAuditRecord 同步 `providerStatus`
- `docs/06-data-interface/fixtures/audit-snapshot-fixtures-v1.json`：四角色最少字段样本 + 禁止字段探测
- `tests/fixtures/loader.ts`：注册 `AUDIT_SNAPSHOT`

### 隐私与越权
- 四角色快照均走既有 AES-GCM envelope + HMAC；不含 API Key/Authorization/完整 header/原始 BM25 score/内部阈值/推理文本
- `rawResponse` 由 provider `scrub()` 去除密钥回显；`baseUrlOrigin` 仅 origin
- `getTraceWorkflow` 为 worker 层只读解密；越权授权在 IPC 层（M6-09/M6-11）处理

### 不包含范围
- `audit.getWorkflow` IPC 与 Renderer 消费（M6-09）
- T-AUD-001 中 hash-chain/非法转换/写失败停服等其余 todo（归属 M1-05/M7-04）

# M5-04 OpenAI-compatible 替代 adapter

## 状态
已完成（2026-08-22，SubAgent 自检通过）

## 实现说明

### 包含范围
- `openai-compatible.ts`：`OpenAiCompatibleProvider extends OpenAiChatCompletionsProvider`，adapterType='OPENAI_COMPATIBLE'——复用 M5-03 共享基类（请求构造/解析/错误映射/审计记录）
- 测试：单测（success/timeout/invalid-output/adapterType/审计无 Key/双 adapter 契约对比）、集成（本地 server：/v1/chat/completions 路径、429、超时、invalid 输出）
- T-PROV-001 的 openai-compatible 三用例已在 M5-03 填充（success/timeout/invalid-output）

### 不包含范围
- Prompt 渲染（M5-05）、输出校验器（M5-06）、编排（M5-07）
- ANTHROPIC_MESSAGES adapter（M5-02 决策：adapterType 收敛为 DEEPSEEK|OPENAI_COMPATIBLE，Anthropic 协议差异留待未来）

### 关键决策
- 第二 adapter 复用同一基类而非复制逻辑，证明业务层无供应商硬绑定（RESEARCH §5.2/§5.3：仅用第三方明确支持的 Chat Completions + JSON Output 子集）
- `OpenAiCompatibleProvider` 与 `DeepSeekProvider` 对相同输入的 wire request / 错误映射 / 成功输出结果一致（双 adapter 对比测试验证 error + success 两条路径）
- 无 baseUrl 硬编码、无模型名写死——一切来自 `ProviderGenerateInput`
- `OpenAiAdapterType` 用 `Extract<ProviderConfigV1['adapterType'], ...>` 从契约派生，不手写枚举子集
- SubAgent 自检修正：T-PROV-001 timeout 用例改用 fixture 声明的 OpenAiCompatibleProvider 驱动、注释去除任务编号、集成测试补请求体协议断言、单测补 tool_choice 断言

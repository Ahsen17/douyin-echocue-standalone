# M5-08 实现全链路时钟、deadline 和 abort

## 状态
已完成（2026-08-22）

## 实现说明

### 包含范围
- `src/main/suggestion/SuggestionAttemptOrchestrator.ts`：完整 deadline 公式（CONTRACT §6）——
  - `freshnessDeadlineMonotonicMs = min(t0 + 3000, selectedAt + 2500, t0 + windowMaxAgeMs)`；`windowOpenedAt` 取候选进入窗口时刻 = 该候选 `receivedMonotonicMs`（t0），第三项 = `t0 + windowMaxAgeMs`（用户确认语义）
  - `maybeStartAttempt` 创建 attempt 时用公式计算最终 deadline，并同步覆盖 `processingComment.freshnessDeadlineMonotonicMs`，使 `attemptFreshness`/`commentCancelled` 单一口径
  - `handleComment` 初值改为 `t0 + min(3000, windowMaxAgeMs)` 作为预 attempt 保守界
  - 展示窗口计时器：`DISPLAYED` 成功后按 `displayDurationMs`（默认 10s，PRD）`setTimeout(finishDisplay)`，`.unref()` 防测试/关闭挂起
  - 计时器清理：`clearAttempt`/`startSession`/`endSession` 统一 `clearDisplayTimer()`，停止后迟到 `finishDisplay` 不会写出 `HIDDEN`/清窗
  - 计时采样：`t1`（筛选完成）记入 `PERSONA_ROUTE` 快照；`t2`（本地输出校验完成）记入直出与 LLM 两条路径的 `OUTPUT_VALIDATION` 快照；`t_end` 已在 `OVERLAY_RESULT`，新增 `e2eMs = t_end - t0`
- `src/main/suggestion/types.ts`：`SuggestionOrchestratorDeps` 新增可选 `displayDurationMs`（默认 10_000）
- `src/main/service/create-controller.ts`：装配 `displayDurationMs: 10_000`
- 保留 provider 5s 硬超时（`PROVIDER_TIMEOUT_MS`），服从更早的新鲜度 deadline；`ABORTED` 归属按本地取消原因（停止/过期 → DISCARDED，5s 保险 → PROVIDER_FAILED）

### 已确认决策
- `windowOpenedAt` = 候选 t0（用户确认）；无需为 SuggestionWindow 增加窗口级时间戳，`WindowSummary.openedAtMonotonicMs` 保持现状
- 当前 `windowMaxAgeMs=1500` 会让有效 deadline 收紧到 `t0+1.5s`（比 E2E 3s / 模型 2.5s 预算更紧）；该值是校准常量（ARCH 注明待 POC-02 校准），公式忠实实现

### 不包含范围
- LLM 路径四角色审计快照（RENDERED_PROMPT/LLM_REQUEST_META/LLM_RAW_RESPONSE/LLM_PARSED_OUTPUT）——M5-09

# M5-01 Provider 配置服务和连接测试

## 状态
已完成（2026-08-22，SubAgent 自检通过）

## 实现说明

### 包含范围
- `ProviderConfigService`：provider 配置读写（`ProviderConfigV1Schema` 校验，含 HTTPS 强制）、API Key 生命周期委托 `CredentialStore`、三态连接测试
- HTTP 传输层 `http.ts`：Node 全局 `fetch`，`redirect:'manual'` + 同源重定向跟随（≤3 跳）+ 跨 host/协议/userinfo/query/fragment 拒绝 + 5s 超时 + abort 归一 + 响应体 1 MiB 上限
- `provider-control-handlers.ts`（纯逻辑，可测）+ `provider-control-ipc.ts`（接线）：`provider.credential.set/clear/test`，`isTrustedSender` 校验，响应不含 Key；providerId 与配置 credentialRef 绑定校验
- 契约：权威 `contracts-v1.ts` 新增 `ConnectionTestResultV1Schema`（三态），同步 `src/contracts/src/schemas.ts` + schemas.test.ts
- 装配：`create-controller.ts` 导出 `ProviderConfigService`；`index.ts` 接入 IPC；preload + `echocue.d.ts` 白名单
- 依赖：根 package.json 显式声明 `zod@3.25.76`（此前仅作为 @echocue/contracts 传递依赖；主进程 IPC 运行时 import zod，按 M0-04 精确锁定）；license:check 645 包无禁止许可、sbom 通过

### 不包含范围
- TextGenerationProvider 稳定接口与 adapter（M5-02/03/04）
- Prompt 渲染、编排、审计快照（M5-05~09）
- 渲染器 UI 配置页（M6-03）

### 关键决策
- HTTP 客户端用 Node 全局 `fetch`，不新增 npm 依赖；生产 https 强制在 `assertSecureHttpsUrl`（传输层）与 `ProviderConfigV1Schema`（配置层）双重生效
- `allowInsecure` 仅为集成测试 loopback http 逃生口，生产调用点永不置位
- 重定向协议规则为「目标协议必须等于当前协议」而非强制 https，使 loopback http 集成测试可行；生产 https 场景下天然禁止 http 降级
- testConnection 三态：200→OK、401/403→AUTH_FAILED、其余（4xx 非 401/403、5xx、网络、超时、损坏配置）→UNAVAILABLE
- SubAgent 自检修正：hasApiKey 改读盘（持久化 Key 不再误报）、providerId 与 credentialRef 绑定、三态类型进契约包、IPC 纯逻辑抽出可测、redirect 目标校验 userinfo/query/fragment、响应体上限、补 TIMEOUT/ABORTED/越权/隐私测试

### 资产修复（范围外但必要）
`assets/douyinLive_linux` 缺执行位（644）导致 douyin 集成测试失败，`chmod 755` 修复（与 M3-07 qdrant_linux 修复同源，M4-01 计划已注明）。

# M5-02 TextGenerationProvider 稳定接口

## 状态
已完成（2026-08-22，SubAgent 自检通过）

## 实现说明

### 包含范围
- `types.ts`（扩展）：`ProviderGenerateInput`（sessionId/traceId/windowVersion/providerId/adapterType/baseUrl/modelId/messages(已渲染 system+user)/apiKey/timeoutMs/freshnessDeadlineMonotonicMs/abortSignal）、`ProviderGenerateResult`（ok/error 判别联合）、`ProviderAuditRecord`（providerRequestId?/providerId/adapterType/baseUrlOrigin/modelId/rawRequest/rawResponse?/normalizedError?，不含 Authorization/Key）、`ProviderMessage`
- `errors.ts`：`mapHttpStatusToProviderError`（401→AUTH、402→BILLING、400/422→VALIDATION、429→RATE_LIMIT、5xx→SERVER，2xx/未处理→null）、`mapProviderErrorToDomain`（CONTRACT §6 固定映射，ABORTED→null 表示走 DISCARDED）、`PROVIDER_ERRORS_V1`
- `TextGenerationProvider.ts`：稳定接口 `generateReply(input): Promise<ProviderGenerateResult>`（SDK 类型不越界）
- 复用 M5-01 `http.ts` 传输层

### 不包含范围
- DeepSeek/OpenAI-compatible 具体 adapter（M5-03/04）
- Prompt 渲染（M5-05）、输出校验（M5-06）、编排（M5-07）

### 关键决策
- `ProviderGenerateInput` 以 CONTRACT §6 `GenerateSuggestionRequest` 为权威，但**不携带** persona/comment/retrievalContext——adapter 只消费已渲染 messages 与身份字段，Prompt 组装属 M5-05
- `mapProviderErrorToDomain(ABORTED)` 返回 null：CONTRACT §6 明确 ABORTED 若由用户停止/窗口变化触发不是用户错误，workflow 走 `DISCARDED` 而非 `FAILED`，故不映射为领域错误
- `PROVIDER_TO_DOMAIN` 用 `Record<Exclude<ProviderErrorV1,'ABORTED'>,DomainErrorV1>` 穷尽类型——新增契约错误码在编译期强制处理，不会静默落入 null
- `timeoutMs` 必填（CONTRACT §6 硬超时 5000ms 是不变量，adapter 不得退化为无界等待）
- `PROVIDER_ERRORS_V1` 由 `ProviderErrorV1Schema.options` 派生，与共享契约永不漂移

### 文档冲突记录
1. **apiKey 与 LLM §2 输入契约**：LLM §2 写"输入对象中不得包含 API Key"。本任务规格与 CONTRACT §6 均要求 adapter 接收调用方解析的 apiKey（仅注入 Authorization header）。取舍：任务规格为直接权威，apiKey 保留在 `ProviderGenerateInput`，但**必须**在 `ProviderAuditRecord`/错误/日志中全程剥离（M5-03 用白名单字段构造 rawRequest 落实）。
2. **LLM §2 与 CONTRACT §6 输入字段不一致**：`GenerateReplyInput`（attemptId/targetComment/persona/safetyPolicy/retrieval）与 `GenerateSuggestionRequest`（sessionId/windowVersion/persona/comment/retrievalContext）两套字段。本任务采用"任务规格 + CONTRACT §6 + 已渲染 messages"组合；建议 M5-05 编排器接入前统一口径（本批不阻塞）。

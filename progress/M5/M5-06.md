# M5-06 实现 golden/LLM 共用输出校验器

## 状态
已完成（2026-08-22，SubAgent 自检通过）

## 实现说明

### 包含范围
- `src/main/validation/SuggestionOutputValidator.ts`：`SuggestionOutputValidator.validate(candidate, context)`——golden 直出 payload 与 LLM 输出共用，按 LLM §5.2 固定 1→7 顺序校验：
  1. 解析（完整 JSON object，顶层数组/非对象 → `JSON_PARSE_FAILED`）
  2. Schema（LLM §5.1 逻辑 schema，`additionalProperties:false` 落实，额外字段/缺失字段/类型错误 → `JSON_SCHEMA_FAILED`；cue 数量 2–3 归步骤 4 不在此判）
  3. 规范化（NFKC + trim；C0/C1/零宽/bidi/连接符/BOM/软连字符 → `UNSAFE_CONTROL_CHAR`，不补齐不改写）
  4. 结构长度（trim 后空/仅标点 → `EMPTY_QUICK_REPLY`；`countHanCharacters>80` → `QUICK_REPLY_TOO_LONG`；数量非 2–3 → `CUE_COUNT_INVALID`；cue 空/仅标点 → `CUE_EMPTY`；>40 → `CUE_TOO_LONG`；去重 → `CUE_DUPLICATE`；超限即拒绝不静默截断）
  5. 安全禁忌（复用 `evaluateInputSafety` 同一冻结 `CompiledSafetyRuleV1[]`；版本化映射 `PII→PERSONAL_INFO_HIT`、`TEAM_FORBIDDEN/编译规则→FORBIDDEN_POLICY_HIT`、其余/engine-error→`RISK_RULE_HIT`）
  6. 人设事实边界（确定性子串：非当前成员 displayName/alias、`forbiddenPromiseTerms`；成员空/当前人设未知 fail-closed → `PERSONA_REVIEW_UNCERTAIN`；当前成员自称允许）
  7. 新鲜度取消（abort→`USER_STOPPED`；session **或 trace** 不符→`STALE_SESSION`；window 不符→`STALE_WINDOW`；超 deadline→`DEADLINE_EXCEEDED`）
  - 通过 → `{ quickReply, cues, source: 'llm' | 'retrieval_payload' }`（用规范化后字符串 + source 盖章）
- `src/main/util/count-han.ts`：`countHanCharacters`（按汉字码点计数，BMP + Ext A–F + 兼容区；Ext-B 代理对按 1；CJK 标点/全半角不计）+ `isOnlyPunctuationOrWhitespace`
- 契约增量：`OutputValidationReasonV1Schema`（13 码）、`SuggestionSourceV1Schema`、`ValidatedSuggestionV1Schema`（展示/IPC 形状，长度不由 maxLength 承担、只留 min 约束，对应 LLM §5.1）；同步权威 `docs/06-data-interface/schema/contracts-v1.ts`（逐字节一致）+ `schemas.test.ts`
- fixture：`output-validation-fixtures-v1.json`（15 用例：正常 LLM/正常 golden 直出共用/81 汉字/Ext-B 80 代理对/仅标点/额外字段/1 条 cue/41 汉字 cue/重复/PII/禁忌/其他成员名/禁忌承诺/STALE_WINDOW/STALE_SESSION(trace)/DEADLINE_EXCEEDED）
- 文档同步：CONTRACT §2 枚举列表补 3 个类型

### 不包含范围
- SuggestionAttempt 编排（M5-07）、时钟/deadline/abort（M5-08）、生成路径全量审计快照（M5-09）
- 状态机 transition 变更：ATLAS §8.2 `DIRECT_READY→DISCARDED` 与权威 `TRACE_TRANSITIONS_V1` 冲突，按契约 golden 校验失败在 RETRIEVING 阶段降级 LLM，不在本任务引入新 transition
- `SuggestionOutputV1Schema`（provider 线）maxLength 不改动；`countHanCharacters` 是权威显示长度层，两处共同收口

### 关键决策
- 长度上限由 `countHanCharacters`（汉字码点）承担而非 JSON Schema maxLength（LLM §5.1）——Ext-B 代理对按 1 汉字，JS `maxLength` 会双重计数
- `ValidatedSuggestionV1Schema` 是跨进程展示形状（M6-07 overlay 渲染），与 provider 线 snake_case `SuggestionOutputV1Schema` 分离
- 输出安全复验复用输入安全同一确定性规则引擎 `evaluateInputSafety`（冻结版本），不另造规则
- 人设边界为确定性负向规则 + fail-closed，模糊/事实一致性覆盖率=版本化 POC 项（`PERSONA_BOUNDARY_RULES_VERSION_V1`）
- 新鲜度含 trace 比对（LLM §5.2 第 7 步的 `trace_id 仍匹配`）；无 `STALE_TRACE` 码，映射 `STALE_SESSION`
- SubAgent 自检修正：补 trace 匹配（Major）、落实 additionalProperties:false（Major）、顶层数组归 JSON_PARSE_FAILED、cue 40 边界补正向用例、`mapSafetyReason` 去死分支且编译 PII 规则归 PERSONAL_INFO_HIT、fixture note 去任务编号、空值判断用 `SUGGESTION_OUTPUT_MIN_REPLY_LENGTH`、隐私断言遍历全部 case

# 技术债务与后续规划

本文档记录暂不进入 MVP 主线，但需要预留或后续补齐的事项。

## lexicon 验证备注

M2 Stage 11 的“优化失败”判断已撤回。此前出现的 `UNAVAILABLE` / timeout 报错来自 Qdrant 测试配置未连通，不作为当前技术债务。

当前保留的优化是：

1. 启动前预热本地 tokenizer。
2. comment batch 分批并发查询，每批最多 5 条。
3. Qdrant query 失败保留日志和 `other` 兜底。
4. 验证脚本输出 raw proto 和 project client 的分段耗时。

## 官方直播状态接口替换

MVP 使用 douyinLive WebSocket `live_status` 系统事件维护直播间开播状态。该事件流可在同一个连接上推送 `ROOM_ONLINE`、`ROOM_ENDED` 和 `ROOM_OFFLINE`。

后续需要评估是否替换为目标平台官方直播状态接口或事件：

1. 保持 AI 服务启动前必须确认直播间开播。
2. 保持下播后服务端自动关闭对应直播间 AI 服务。
3. 保持 client 收到下播消息后自动停止服务。
4. 官方状态接口替换不得改变规则门禁和回放审计语义。

## 平台规则发布预告

平台 global 规则是最高优先级硬规则。正式发布前必须由平台完成自检；存在冲突、歧义或不可应用问题时不允许发布。

后续预留发布预告能力：

1. 公告新规则、发布时间和影响范围。
2. 提供整改建议。
3. global 规则不进入下级整改逻辑；下级只整改机构 scope 或直播间 scope 的适配问题。

## 规则检测与整改

规则冲突检测必须由服务端执行，client 只展示通知、整改入口和结果。

后续实现原则：

1. 服务端不在规则发布后全量扫描直播间。
2. 个人直播间在开播前按适用规则版本惰性检测。
3. 机构账户收到 global 新版本后立即整改机构 scope 规则。
4. 机构规则未整改时，受影响且尚未开播的直播间不能启动 AI 服务。
5. 已开播直播间不强制中断，本场继续使用已锁定版本。

## 主体档案增强

MVP 只支持单主播或团队整体档案。

后续预留：

1. 多人独立档案。
2. 团队整体风格与成员风格组合。
3. 当前发言人或互动场景切换。
4. 草稿、发布、版本回溯和变更审计。

## 人设样例沉淀

MVP 主体档案只维护基础人设、语言风格、口头禅和禁忌边界。

后续预留：

1. 从回放中标记优秀回复。
2. 将优秀回复沉淀为档案样例。
3. 样例按版本归档。
4. 运行时可选择是否注入样例上下文。

## 直播场景识别

MVP 暂不识别直播场景，回复只基于弹幕原文 / 概要和主体档案。

后续预留：

1. 手动选择闲聊、讲品中、上链接前、抽奖、连麦、下播前等场景。
2. 结合直播状态、弹幕内容和平台事件自动判断场景。
3. 场景只作为互动回复辅助上下文。

## 高级触发与排序

MVP 使用固定窗口扫描和高价值弹幕提前触发。

后续预留：

1. 点赞、回复、重复提及等平台互动事件作为排序信号。
2. 按直播间配置互动价值阈值、冷静期和扫描周期。
3. 回放 Top N 候选和排序原因。
4. 持久化低置信度、不安全、不符合人设等不推送原因。

## client 本地审计

MVP 不实现 client 本地审计。浮窗展示记录、会话本地留存、CSV 导出、本地清理和权限过滤均作为后续能力。

后续预留：

1. 按直播间和 AI 服务会话查看本地展示记录。
2. 保存弹幕原文 / 概要、短回复、提词和 `message_id`。
3. 支持保留期、手动清理、筛选和导出。
4. 打开本地记录时按当前直播间权限过滤。

## OBS 捕捉排除

MVP 只验证 Windows client 浮窗展示和基础交互，不把 OBS 捕捉排除作为 MVP 验收项。

后续作为 Windows client 专项能力评估：

1. 验证 `SetWindowDisplayAffinity` 在目标 Windows 版本、显卡驱动和 OBS 捕捉模式下的实际表现。
2. 验证 Electron 内容保护能力是否能稳定排除窗口捕捉。
3. 区分显示器捕捉、窗口捕捉、游戏捕捉等 OBS 场景。
4. 形成兼容性矩阵和失败降级提示。

## 权限模型增强

MVP 权限核心为平台用户、个人认证账户、机构认证账户、机构成员和直播间权限。

后续预留：

1. 邀请确认流程。
2. 机构成员权限审计。
3. 受邀个人直播间更细颗粒只读授权评估。
4. 机构自有直播间按查看、配置、回放、浮窗连接管理授权。

## 回放审计增强

MVP 回放保存 Top N 候选、评分原因、主体档案版本、规则版本、生成结果和推送结果。

后续预留：

1. 按直播间、触发来源、互动类型、安全结果查询。
2. 回放时还原主体档案版本和规则版本。
3. bad case 标注和原因归类。
4. 基于回放数据优化评分、触发和生成。

# 产品范围

## 目标

构建一个直播间实时互动助手 MVP：消费直播间实时弹幕，识别有梗、玩笑、互动感强、夸主播 / 团队或人设相关的弹幕，并基于直播间主体档案生成短回复和提词，通过 client 展示到主播浮窗。

MVP 优先验证主链路：

1. douyinLive 或模拟弹幕流接入。
2. 弹幕聚合与互动价值识别。
3. 直播间主体档案配置和版本引用。
4. Workflow 驱动的短回复与提词生成。
5. 自动安全判断与不推送拦截。
6. client 接收服务端推送并展示浮窗。
7. Workflow 全量持久化，用于回放和审计。

只有具备接话、延展话题、带动气氛或强化主体人设价值的弹幕，才进入互动生成。

## 平台与用户

- 第一目标平台：抖音直播。
- MVP 输入来源：douyinLive WebSocket 事件流或预设弹幕模拟流。
- MVP 直播状态来源：douyinLive `live_status` 系统事件。
- 后续输入来源：官方接口，形态为 HTTP 控制 + WebSocket 实时事件流。
- 产品方向：架构按 SaaS 化预留，MVP 优先完成主要链路验证。
- 主要用户：
  - 主播：通过 client 浮窗读取弹幕概要、短回复和提词。
  - 平台用户：系统登录身份，可开户认证为个人账户或机构账户。
  - 个人认证账户：只能绑定并管理一个自有直播间。
  - 机构认证账户：可管理多个机构自有直播间，并按直播间授权机构成员。

client 是主播端与服务端交互的主体。服务端向 client 推送 AI 回复，浮窗只展示 client 接收到的内容，不直接与服务端通信。

## 直播间主体档案

一个直播间唯一对应一个直播主体档案。主体可以是单个主播，也可以是直播团队整体；不同主体必须对应不同直播间。

MVP 主体档案支持手动编辑：

| 字段 | 业务解释 |
| --- | --- |
| 基础人设 | 主播或团队的身份、定位、性格和互动边界。 |
| 语言风格 | 回复语气、表达节奏、幽默方式和亲密度。 |
| 口头禅 | 可被生成回复引用的固定表达。 |
| 禁忌边界 | 不应触碰的话题、梗、表达方式和风险点。 |

主体档案持久化到数据库，并进行版本管理。每次发布生成不可变版本，运行时只引用当前已发布版本，Workflow 回放记录保存档案 ID 和版本号。

## Web 管理端能力

Web 管理端支持：

- 平台用户登录。
- 开户认证状态管理。
- 机构成员和直播间权限管理。
- 直播间主体档案编辑与发布。
- 触发配置编辑。
- 平台、机构、直播间三层安全规则管理。
- Workflow 历史列表和详情。
- 规则冲突、主体档案缺失、权限不足等整改页面。

未认证账号只看到登录和认证引导；个人认证账号看到自己的直播间和配置；机构认证账号看到机构、成员、直播间和回放。受邀个人直播间在机构下可被机构查看基础状态和回放，但机构不能修改该个人直播间配置。

client 只展示通知和跳转入口，具体整改和配置调整在 Web 管理端执行。client 跳转 Web 整改页时携带 `room_id` 和 `issue_type`。client 登录后，打开 Web 管理端时通过一次性跳转 token 完成免登录。

Web 管理端 Workflow 回放普通用户只看业务摘要；平台管理员可查看技术详情。技术详情必须隐藏 API Key、连接串、内部路径、密钥类配置等敏感字段，可展示 provider 名称、model_id、错误摘要、耗时和 token usage。

## client 与浮窗能力

client 是 AI 助手本体，负责登录、选择直播间、启动 AI 服务、接收服务端推送、维护心跳和管理浮窗。

MVP client 约束：

- 一个平台用户同一时间只能登录一个 client。
- 一个 client 同时只启用一个直播间 AI 服务。
- 同一直播间同一时间只允许一个 active client。
- client 每 10 秒发送心跳；服务端连续 30 秒未收到心跳则判定断线，立即停止该 client 持有的 AI 服务并释放锁。
- 正常退出或关闭 client 前，必须先停止 AI 服务。
- client 只提示规则整改、主体档案缺失、权限不足等阻断原因；具体调整在 Web 管理端完成。
- 启动失败时展示失败原因和对应动作，例如重试或跳转 Web 管理端整改。
- Web 整改后，client 提供“我已调整”动作；检测通过后重新执行完整启动门禁，并自动启动 AI 服务。
- 下播自动停止时，client 以 Toast 提示“直播已结束，AI 助手已停止”。
- 心跳断线恢复后，client 提示“连接中断，AI 助手已停止”，并提供重新启动按钮。
- 被其他 client 接管时，当前 client 停止 AI 服务并提示“该直播间已在其他设备启动”。
- 运行中如果连续 3 轮 AI 生成失败，client 显示非阻断提示“AI 生成暂时异常，正在自动恢复”。

Windows 浮窗采用半透明小面板形态，面向主播扫读。

MVP 浮窗必须支持：

- 置顶。
- 半透明背景。
- 拖拽移动。
- 点击穿透。
- 一键隐藏 / 显示。
- 字号调节。
- 明暗主题。
- 展示弹幕原文 / 概要、短回复和提词。

MVP 浮窗默认配置为：中等窗口，水平居中，垂直靠下，毛玻璃透明度 60%，文字不透明，字号 20，暗色主题，置顶开启，点击穿透开启。新消息到达时直接覆盖当前消息。

client 启动页最小展示登录状态、当前账户类型、直播间选择、直播状态和启动按钮。运行中页面最小展示当前直播间、运行状态、连接状态、最近一条推送状态和停止按钮。client 不展示 Workflow、Agent、模型、规则扫描等底层技术状态，只展示主播可理解的使用状态。

第一阶段目标系统为 Windows。OBS 捕捉排除不作为 MVP 验收项，后续作为 Windows client 专项能力评估 `SetWindowDisplayAffinity` / Electron 内容保护等方案。
